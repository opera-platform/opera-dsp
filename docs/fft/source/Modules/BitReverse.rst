BitReverse Module
=================

The `BitReverse` module is a streaming frame reordering buffer.
It accepts a frame of complex samples, stores each accepted sample at the bit-reversed value of the write counter, and then reads the stored frame back with a normal increasing read counter.
This applies a bit-reversal permutation to the frame: natural-order input becomes bit-reversed output, and bit-reversed input becomes natural-order output.

It is used by the top-level :doc:`FFT <FFT>` wrapper when ``useBitReverse`` is enabled.

BitReverseParams
----------------

**Definition:**

.. code-block:: scala

  case class BitReverseParams(
    dataType     : DspComplex[FixedPoint],
    memDepth     : Int,
    runTime      : Boolean = false,
    singlePortMem: Boolean = false
  )

**Parameter descriptions:**

- ``dataType``  
  Complex FixedPoint type stored in the bit-reversal buffer.

- ``memDepth``  
  Maximum number of samples in the frame. When used by the FFT wrapper, this is set to ``FFTParams.fftSize``.

- ``runTime``  
  If ``true``, enables runtime frame size selection through ``i_samples``.

- ``singlePortMem``  
  If ``true``, uses single-port memories for the internal buffers.

**Requirements:**

- Active frame sizes are expected to be powers of two and must not exceed ``memDepth``.
- When ``runTime`` is disabled, the active frame size is ``memDepth``.
- When ``runTime`` is enabled, ``memDepth`` is the maximum frame size and ``i_samples`` selects the active frame size.

IOs
---

`BitReverse` has the following I/O signals:

.. code-block:: scala

  class BitReverseIO(val params: BitReverseParams) extends Bundle {
    val in : DecoupledIO[DspComplex[FixedPoint]] = Flipped(Decoupled(params.dataType))
    val out: DecoupledIO[DspComplex[FixedPoint]] = Decoupled(params.dataType)

    val i_last: Bool = Input(Bool())
    val o_last: Bool = Output(Bool())

    val i_samples: Option[UInt] = if (params.runTime) Some(Input(UInt(log2Ceil(params.memDepth + 1).W))) else None
  }

- ``in`` and ``out`` are Decoupled complex data streams.
- ``i_last`` is carried as part of the stream interface, but the configured frame length drives the internal counter wrap.
- ``o_last`` is generated when the read counter reaches the final sample of the active frame.
- ``i_samples`` selects the active frame size when runtime sizing is enabled.

Module Operation
----------------

`BitReverse` uses two internal memories as a double buffer.
The first frame is written before any output is available.
After one frame has been stored, the module can write the next frame into one memory while reading the previous frame from the other memory.

The write address is generated by reversing the low address bits of the write counter.
For example, in an 8-sample frame, input sample indices ``0, 1, 2, 3, 4, 5, 6, 7`` are written to addresses ``0, 4, 2, 6, 1, 5, 3, 7``.
The read address is the normal read counter, so the output frame is read from addresses ``0`` through ``7``.

The number of reversed address bits is selected from the active frame length.
When ``runTime`` is disabled, the active frame length is ``memDepth``.
When ``runTime`` is enabled, ``i_samples`` selects the active frame length and determines where the read and write counters wrap.
Inside the FFT wrapper, ``memDepth`` is ``FFTParams.fftSize``; in runtime mode this is the maximum FFT size, while ``i_samples`` is driven by the active FFT size.

Input is ready while the block is writing or writing and reading; input is stalled when both internal memories hold unread data and the block must finish a read-only frame.
Output is valid only after a complete frame has first been written.

The state machine has four states:

- ``s_idle``: Initial state before writing starts.
- ``s_write``: Writes a frame while no output frame is available.
- ``s_write_read``: Writes a new frame while reading the previous frame.
- ``s_read``: Reads a stored frame while input is stalled.

SystemVerilog Generation
------------------------

You can generate SystemVerilog for the `BitReverse` block.

Use the following command in the project root folder:

.. code-block:: bash

   sbt "fft/runMain opera.fft.BitReverseApp"

This will generate SystemVerilog files in the ``./rtl/BitReverse`` directory.

If you want to modify the BitReverse configuration, edit the ``params`` definition in the `BitReverseApp` object.

Tests
-----

To run tests, use the following command in the project root folder:

.. code-block:: bash

   sbt "fft/testOnly opera.fft.BitReverseSpec"

The tests cover frame output order for static and runtime frame sizes, including ``memDepth`` and ``memDepth / 2`` runtime selections.
They also cover single-port memory configurations and verify ``o_last`` alignment with the reordered output frame.

Output directory is ``fft/test_run_dir/`` when tests are run from the project root.
